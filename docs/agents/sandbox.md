# Contain Engine-run Agents on the Host

Design for [#15](https://github.com/ralfboltshauser/agent-mail-client/issues/15) and [M6](https://github.com/ralfboltshauser/agent-mail-client/issues/30). [ADR 0004](../adr/0004-confine-the-agent-runner-on-the-host.md) records the boundary. The [Mac proof](headless.md) exercises the CLI controls.

## Process and filesystem

- Run the Engine as `amc` and the runner as the owner’s Unix user (`ralf` on this Host). Keep the Engine’s database, blobs, encryption key and provider credentials accessible only to `amc`. The Mac is an external Client and a development target. [ADR 0002](../adr/0002-agents-run-through-the-owners-harness.md) · [ADR 0003](../adr/0003-engine-runs-as-its-own-user.md)
- Use a system-managed runner unit with `User=ralf` and per-run process containment. Start each run with an empty mode-0700 working directory, private temp space, a restrictive umask and absolute CLI paths. Mount the runtime read-only. Hide the rest of the owner’s home, project trees, mail clients, Engine files, other processes’ credentials, and SSH, D-Bus, Docker and T3 control sockets. Leave project access for M8, with a separate read-only mount for the project the owner selected.
- Share only the Harness login state necessary for the installed CLI, including its refresh locks and atomic writes. AMC never copies, reads or refreshes model credentials. Give the CLI a controlled view of HOME, with isolated scratch and session state. A read-only bind of a token file can break refresh by rename. A writable mount of all of HOME exposes too much. Verify whether each CLI can share the real login and refresh successfully with a narrow mount or credential-store access. If it cannot, keep that adapter off until the owner revisits ADR 0002.
- Build the environment from an allow-list (runtime PATH, HOME, temp, locale and the run’s MCP credential if required). Close all inherited file descriptors apart from controlled standard I/O. Strip API and provider credentials, proxy overrides, credential-helper and agent sockets, shell startup variables and inherited Harness overrides. Never put a real bearer in process arguments. Keep it in per-run memory, a private file, or a local forwarding process scoped to that run. Disable session persistence and strip sensitive output from logs.
- Enforce `NoNewPrivileges=yes`, no supplementary privileged groups or capabilities, and isolation from host control sockets. Test privilege elevation from inside confinement. Passwordless sudo on the Host still weakens ADR 0003 for arbitrary external processes running as `ralf`. This runner design does not change that host-wide setting. [systemd execution controls](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html)

## Network and tool exposure

- Put the worker in a restricted network namespace. Default deny outbound connections and expose only an AMC MCP forwarding endpoint and a destination-aware egress proxy for the installed CLI’s first-party inference and login refresh. Learn the required destinations in a service-context run with synthetic data. Enforce destination policy outside the worker, including redirects, DNS and IPv6. Deny direct SMTP/IMAP, mail and messaging APIs, arbitrary web, Host loopback services, LAN and tailnet. The worker can reach AMC mail only through scoped MCP. IP-only allow-lists on shared hosting cannot replace destination policy.
- Claude Agent SDK should target the installed binary with `settingSources: []`, `strictMcpConfig: true`, empty built-in `tools`, and explicit MCP permissions. Check SDK-to-CLI behavior and managed settings before using mail. Codex `app-server` should run with a sanitized config view, explicit tool overrides and read-only command sandbox. The Mac `exec --ignore-user-config` result does not establish the equivalent on `app-server`. Reject unexpected servers, hooks, plugins or execution tools. Server-side scope checks apply even if a Harness advertises extra tools.
- Queue at most two concurrent runs. Set a wall-clock deadline plus output, process, memory and scratch limits. On exit, timeout or setup failure, revoke the run token, kill the per-run cgroup and remove scratch. A later retry receives a fresh grant.

## Before enabling either adapter

From the actual Host service context, check subscription auth and refresh, positive JSON and fixture MCP calls, forbidden tool calls, owner-config and hook fixtures, access to dummy files and sockets outside the sandbox, attempted elevation and disallowed egress. Include cancellation with descendants. Prove the restrictions with canaries, then enable one adapter at a time. The separate issue for that Host run is [#7](https://github.com/ralfboltshauser/agent-mail-client/issues/7).

Outside T3 Code, Claude Code, and Codex sessions are owner-managed processes. AMC controls what their specific token can do in the Engine. Their local tools, unrelated credentials and network access follow the outside client’s own policy. [Permission model](permissions.md)
