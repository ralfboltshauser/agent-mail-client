# Contain Engine-run Agents on the Host

Design for [#15](https://github.com/ralfboltshauser/agent-mail-client/issues/15) and [M6](https://github.com/ralfboltshauser/agent-mail-client/issues/30). [ADR 0004](../adr/0004-confine-the-agent-runner-on-the-host.md) records the boundary. The [Mac proof](headless.md) exercises the CLI controls.

## Process and filesystem

- Run the Engine as `amc` and the runner as the owner’s Unix user (`ralf` on this Host). Keep the Engine’s database, blobs, encryption key and provider credentials accessible only to `amc`. The Mac is an external Client and a development target. [ADR 0002](../adr/0002-agents-run-through-the-owners-harness.md) · [ADR 0003](../adr/0003-engine-runs-as-its-own-user.md)
- Use a system-managed runner with `User=ralf`. A privileged Host launcher creates a private PID namespace, mounts a fresh procfs for that namespace, and starts each Harness and its descendants in their own cgroup, mount and network namespaces. No Host procfs, inherited Host process handles or namespace-entry capabilities are available inside a run. Start each run with an empty mode-0700 working directory, private temp space, a restrictive umask and absolute CLI paths. Mount the runtime read-only. Hide the rest of the owner’s home, project trees, mail clients, Engine files, other processes’ credentials, and SSH, D-Bus, Docker and T3 control sockets. Leave project access for M8, with a separate read-only mount for the project the owner selected.
- Share only the Harness login state necessary for the installed CLI, including its refresh locks and atomic writes. AMC never copies, reads or refreshes model credentials. Give the CLI a controlled view of HOME, with isolated scratch and session state. A read-only bind of a token file can break refresh by rename. A writable mount of all of HOME exposes too much. Verify whether each CLI can share the real login and refresh successfully with a narrow mount or credential-store access. If it cannot, keep that adapter off until the owner revisits ADR 0002.
- Build the environment from an allow-list (runtime PATH, HOME, temp, locale and a local MCP endpoint if required). Close all inherited file descriptors apart from controlled standard I/O. Strip API and provider credentials, proxy overrides, credential-helper and agent sockets, shell startup variables and inherited Harness overrides. The Engine hands its short-lived bearer to a trusted per-run forwarder outside the worker namespaces, under a service identity inaccessible to the worker. The forwarder pins the Engine origin, accepts only MCP initialization and tool traffic through the private run endpoint, rejects resource and other methods, and injects the bearer upstream. The Harness receives only that local endpoint. No Engine bearer enters its arguments, environment, files or file descriptors. Disable session persistence and strip sensitive output from logs.
- Enforce `NoNewPrivileges=yes`, no supplementary privileged groups or capabilities, and isolation from host control sockets. Test privilege elevation from inside confinement. Passwordless sudo on the Host still weakens ADR 0003 for arbitrary external processes running as `ralf`. This runner design does not change that host-wide setting. [systemd execution controls](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html)

## Network and tool exposure

- Put the worker in a restricted network namespace. Default deny outbound connections and expose only an AMC MCP forwarding endpoint and a destination-aware egress proxy for the installed CLI’s first-party inference and login refresh. Learn the required destinations in a service-context run with synthetic data. Enforce destination policy outside the worker, including redirects, DNS and IPv6. Deny direct SMTP/IMAP, mail and messaging APIs, arbitrary web, Host loopback services, LAN and tailnet. The worker can reach AMC mail only through scoped MCP. IP-only allow-lists on shared hosting cannot replace destination policy.
- Gate Claude Agent SDK and Codex app-server separately on the [effective inventory checks](headless.md#adapter-activation). Server-side scopes and OS confinement apply independently.
- Queue at most two concurrent runs. Set a wall-clock deadline plus output, process, memory and scratch limits. On exit, timeout or setup failure, revoke the run token, kill the per-run cgroup and remove scratch. A later retry receives a fresh grant.

## Before enabling either adapter

From the actual Host service context, check subscription auth and refresh, positive JSON and fixture MCP calls, forbidden tool calls, owner-config and hook fixtures, access to dummy files and sockets outside the sandbox, attempted elevation and disallowed egress. Include cancellation with descendants. Run two simultaneous jobs with distinct scopes (read and organize). Use dummy secrets in the sibling and an ordinary owner process. Assert cross-run and Host PID lookup, signaling, tracing, procfs/env/fd reads and access to the other forwarder all fail. Verify the read-only job cannot organize and each job can execute its own allowed call. Inspect worker inputs for the dummy Engine bearer. Enable each adapter only after its inventory and these canaries pass. The separate issue for that Host run is [#7](https://github.com/ralfboltshauser/agent-mail-client/issues/7).

On the Mac, a private scratch directory, scrubbed environment and process-group cleanup do not isolate same-UID processes. Run the local fixture with synthetic data and fixture-only credentials. The Mac is not a production runner.

Outside T3 Code, Claude Code, and Codex sessions are owner-managed processes. AMC controls what their specific token can do in the Engine. Their local tools, unrelated credentials and network access follow the outside client’s own policy. [Permission model](permissions.md)
