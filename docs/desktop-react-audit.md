# Desktop React audit

Baseline [`eea5414`](https://github.com/ralfboltshauser/agent-mail-client/tree/eea54148840d79e6558261568b1a59e6abd12725), with Electron 45.4.1, React 19.3.1, Vite 8.3.8, and `@vitejs/plugin-react` 6.3.0. Source links refer to the audited implementation.

A successful background refresh retains the current mail DOM and still re-executes every mounted row body. A failed list refresh really does remove the list. Composer typing stays inside the composer but re-renders the whole dialog and stages the body synchronously through Electron. These paths need different fixes.

## Measurements

`pnpm install --frozen-lockfile` and `pnpm --filter @amc/desktop build` succeeded. For render counts, a temporary Electron test window at 1280 × 900 loaded the Vite dev renderer with the repository's [synthetic mail fixture](../apps/desktop/src/renderer/src/dev/mail-fixture.ts#L12) and a fresh `--user-data-dir` in `/tmp`. The window used neither the production preload nor an Engine or paired profile. A fixture wrapper cloned replies to approximate IPC identities, counted API calls, and could deliver a status or change event, change one row, delay replies, or reject the list query. The changed-event probe invoked the callbacks registered through `onChanged`. It bypassed main-process coalescing.

Temporary layout-effect counters measured committed component renders after initial settle, with development Strict Mode enabled. The row count is inline row bodies processed across committed `ThreadList` renders. DOM identity checks compared list, row, reader, and editor nodes before and after. The input probe used Chromium text insertion with an active editor or input and checked the resulting text. Reset the counters for every action. Counts for immediate events use a 160 ms window, staggered replies use a 330 ms window with successive API replies 32 ms apart, and keystrokes use a 70 ms window to exclude the 550 ms autosave. A zero means the instrumented component had no committed render.

Each no-op change called eight fixture methods once across ten callbacks. The eight methods were accounts, labels, counts, threads, thread, active hand-off, triage counts, and organise errors. Filter and search-summary callbacks also ran and returned local defaults in the unfiltered Inbox. Status-only events made zero API calls. Each body character called `stageComposeBody` once. Subject characters made zero calls during the keystroke window. The stable paths retained all eight row nodes and the selected reader, and retained the editor where open. Electron reported exactly one main-frame navigation, the initial load, during the complete run.

With a synthetic `threads` failure during background refresh, **8 of 8 row nodes detached**, the list disappeared, and the reader heading stayed connected. The next event put eight newly mounted rows on screen within 150 ms, before the delayed 280 ms list response. This isolates the error branch and subsequent error clearing from a real change in mail data.

The eight-row fixture measures the update paths, not production frame timing, IPC latency, a large mailbox, or the owner's exact workload. Staggering is a sensitivity check for separate reply tasks. The fixture's draft-staging method is a no-op, so the typing experiment counts calls and does not time production SQLite or synchronous IPC. No real mail was used.

## Ranked findings

### 1. High · Replica and status updates re-render unrelated regions

**Symptom.** An off-reader change reprocesses the reader and every mounted row. Independent replies can multiply those commits. A timestamp-only event commits the whole shell even with no data reads.

**Root cause.** [`sync.ts:65`](../apps/desktop/src/main/sync.ts#L65) emits a new status object on every patch. [`sync.ts:238`](../apps/desktop/src/main/sync.ts#L238) emits changed for actual changes or organise failures and updates `lastSyncAt` even on an empty pull. Bootstrap emits progress and change per page at [`sync.ts:198`](../apps/desktop/src/main/sync.ts#L198). Main coalesces sync-driven changed events for 120 ms while forwarding status separately at [`main/index.ts:192`](../apps/desktop/src/main/index.ts#L192) and [`main/index.ts:218`](../apps/desktop/src/main/index.ts#L218). Optimistic organise changes and hand-off actions also broadcast changes. [Preload](../apps/desktop/src/preload/index.ts#L80) gives each listener a payload-free changed notification. [`app.tsx:206`](../apps/desktop/src/renderer/src/app.tsx#L206), [`app.tsx:230`](../apps/desktop/src/renderer/src/app.tsx#L230), and [`app.tsx:268`](../apps/desktop/src/renderer/src/app.tsx#L268) own eight subscriptions in `MailApp`. The [sidebar](../apps/desktop/src/renderer/src/components/app-sidebar.tsx#L132) adds triage counts and [`useOrganise`](../apps/desktop/src/renderer/src/components/organise.tsx#L74) checks notices. [`use-amc.ts:20`](../apps/desktop/src/renderer/src/hooks/use-amc.ts#L20) writes fresh replies straight into state. Replica reads parse fresh objects, and its thread-list query returns up to 5,000 rows by default. [`replica.ts:299`](../apps/desktop/src/main/replica.ts#L299) [`replica.ts:360`](../apps/desktop/src/main/replica.ts#L360)

[`App`](../apps/desktop/src/renderer/src/app.tsx#L56) subscribes to the whole status and forwards it plus a new toggle closure. `MailApp` creates sidebar and composer handlers, a hotkey map, and palette actions during those renders. [`app.tsx:472`](../apps/desktop/src/renderer/src/app.tsx#L472) [`app.tsx:612`](../apps/desktop/src/renderer/src/app.tsx#L612) [`app.tsx:883`](../apps/desktop/src/renderer/src/app.tsx#L883) The shadcn sidebar already memoizes its context and receives a stable controlled setter. The hotkey listener uses a ref and rebinds on enablement changes. [`ui/sidebar.tsx:68`](../apps/desktop/src/renderer/src/components/ui/sidebar.tsx#L68) [`ui/sidebar.tsx:112`](../apps/desktop/src/renderer/src/components/ui/sidebar.tsx#L112) [`use-hotkeys.ts:14`](../apps/desktop/src/renderer/src/hooks/use-hotkeys.ts#L14)

**Fix.** Give the shell a pairing-gate selector, the sync indicator the status values it displays, and mailbox regions their own data subscriptions. Reconcile replies by domain ID and preserve unchanged values. Keep the existing broad notification as a compatibility fallback, then narrow IPC invalidation after measuring real query churn. The active hand-off query reaches Engine-backed code and deserves its own selected-thread key and invalidation policy. Preserve observation of remote termination and expiry. [`main/index.ts:424`](../apps/desktop/src/main/index.ts#L424)

### 2. High · Error, resnapshot, and navigation can replace visible content

**Symptom.** A background failure replaces cached rows with an error panel, then a retry puts them back. An account or view change can briefly paint old rows under the new heading or select a row from the old list. An explicit full-history search clears the old hits while pending. These scenarios differ from a successful refresh of the same query.

**Root cause.** [`use-amc.ts:13`](../apps/desktop/src/renderer/src/hooks/use-amc.ts#L13) retains one value across both refreshes and dependency changes. It tracks a generation but does not associate the retained value with a query key. Failure is cleared at refresh start. [`app.tsx:709`](../apps/desktop/src/renderer/src/app.tsx#L709) uses failure to remove `ThreadList` even when rows still exist. Account and view actions reset selection, then the [selection effect](../apps/desktop/src/renderer/src/app.tsx#L320) reads derived rows that can still come from the old query. [`runSearch`](../apps/desktop/src/renderer/src/app.tsx#L359) clears hits eagerly and changes selection on completion. The reader already checks the selected ID against the response, but also depends on the selected summary being present in the current list. On resync, [`sync.ts:154`](../apps/desktop/src/main/sync.ts#L154) and [`sync.ts:182`](../apps/desktop/src/main/sync.ts#L182) can clear the replica, then publish partial snapshot pages. A partial empty result can drive selection to null and unmount the reader. These navigation and resnapshot sequences follow from the code and were outside the timed fixture cases.

**Fix.** Model first load, cached data plus refresh, cached data plus refresh error, and a successful empty result separately. Keep the listbox, reader scroll container, and last successful data mounted on a same-key refresh/error. Show errors in a bounded inline region with retry. Associate selection and list order with the current account/view/filter/search key and reconcile selection only against an authoritative result for that key. Show a same-key cache or a bounded placeholder on account changes, and suppress messages from a different account or thread. Preserve a previously populated Inbox through an in-progress resnapshot of the same pairing until authoritative data is available. Clear display data promptly if pairing or account identity changes. Add tests for delayed and reordered results, a truly empty result, a notification-open target, and the independent search request generation.

### 3. High · Composer typing and unchanged polls do broad work

**Symptom.** Every tested body and subject character commits the composer and its unchanged recipient field. An idle composer commits on each unchanged poll. Body edits also take a blocking persistence path in production.

**Root cause.** The per-draft Yjs document is stable for the mounted Composer. Its local update handler encodes the full document, sends a staged update, then increments React `version`. The bridge calls Electron `sendSync` and main upserts to SQLite with `DatabaseSync`. The autosave effect has no dependency array, so any committed composer render can tear down and reschedule a pending timer. On the clean 1.5 s poll path, equality against the baseline revision passes, then `adopt` allocates header state and assigns attachment state again. Tiptap's installed `useEditor` defaults to skipping transaction-driven React renders. AMC's own Yjs listener accounts for the measured body commits. [`composer.tsx:108`](../apps/desktop/src/renderer/src/components/composer.tsx#L108) [`composer.tsx:169`](../apps/desktop/src/renderer/src/components/composer.tsx#L169) [`composer.tsx:188`](../apps/desktop/src/renderer/src/components/composer.tsx#L188) [`composer.tsx:200`](../apps/desktop/src/renderer/src/components/composer.tsx#L200) [`composer.tsx:286`](../apps/desktop/src/renderer/src/components/composer.tsx#L286) [`preload/index.ts:60`](../apps/desktop/src/preload/index.ts#L60) [`main/index.ts:459`](../apps/desktop/src/main/index.ts#L459) [`draft-updates.ts:21`](../apps/desktop/src/main/draft-updates.ts#L21)

**Fix.** First isolate the edited field, editor, format toolbar, footer, and session persistence. Start the existing debounce from the edit path, subscribe UI to meaningful dirty/save/error transitions, and suppress equal poll results with a contract that accounts for mirror flags and payload changes as well as revision. Preserve remote update origin filtering, autosave ordering, reviewed-revision discard and send, uncertain-send request identity, attachments, and minimise/rehydrate behavior. Profile synchronous staging with a synthetic SQLite-backed harness before changing it. Retain the current crash-recovery contract until a replacement proves equivalent durability. A blind debounce of `stageComposeBody` would widen the window for lost body edits.

### 4. Medium · Virtualization bounds mounted rows but all of them run on parent commits

**Symptom.** Eight row bodies run even when seven rows and the selection are unchanged. Reordering can scroll the selected row into view during sync.

**Root cause.** [`thread-list.tsx:34`](../apps/desktop/src/renderer/src/components/thread-list.tsx#L34) virtualizes with 74 px rows and 12 overscan. React uses stable `t.id` keys. The virtualizer defaults to index keys, and each mounted row's JSX, date and participants formatting, handlers, and style are built inline at [`thread-list.tsx:64`](../apps/desktop/src/renderer/src/components/thread-list.tsx#L64). The selection reveal effect depends on the index, which changes when a sync inserts or reorders rows above the selection. `self` and label lookup identities also change when freshly parsed account and label data arrive. [`app.tsx:228`](../apps/desktop/src/renderer/src/app.tsx#L228)

**Fix.** Keep TanStack Virtual, give it `getItemKey` keyed on the thread ID, and let a small positioning wrapper own index/offset and ARIA metadata. Put row contents in a memoized component with stable callbacks and stable selected values or an entity selector. Bind selection and focus to thread ID and reveal on explicit navigation. Test insertions above the viewport, selected-thread removal, and keyboard focus with `aria-activedescendant`. Desktop commands should keep their existing behavior while one changed row can update without evaluating its siblings.

### 5. Medium · Reader body identity changes can cause local flicker and layout shifts

**Symptom.** Long or HTML messages can show a skeleton again or change height as body content arrives. These are reader-specific risks from source inspection. The eight-row fixture uses plain text.

**Root cause.** [`replica.ts:369`](../apps/desktop/src/main/replica.ts#L369) eagerly loads recent and unread bodies. [`thread-view.tsx:101`](../apps/desktop/src/renderer/src/components/thread-view.tsx#L101) chooses between top-level messages and stateful older groups based on loaded body and unread status. A change can move a message across that tree and reset expansion state. The HTML request effect can cancel and restart an in-flight fetch on a freshly cloned attachments array, and its successful local cache has no explicit revision invalidation. Plain deferred text keys on `bodyRevision` and mounts a skeleton again on revision changes. [`thread-view.tsx:186`](../apps/desktop/src/renderer/src/components/thread-view.tsx#L186) [`thread-view.tsx:277`](../apps/desktop/src/renderer/src/components/thread-view.tsx#L277) [`message-body.tsx:56`](../apps/desktop/src/renderer/src/components/message-body.tsx#L56) starts at 120 px, measures after iframe load, and creates a new observer on every load without disconnecting the previous one until unmount. Toggling remote content replaces `srcDoc`. Renderer's normal UI uses system font fallbacks in [`styles.css:73`](../apps/desktop/src/renderer/src/styles.css#L73), with no app-managed asynchronous font identified. Composer inline previews are another local geometry check because the image loads asynchronously. [`composer.tsx:58`](../apps/desktop/src/renderer/src/components/composer.tsx#L58)

**Fix.** Use stable per-message presentation state and cache bodies by message ID plus a revision that covers the requested representation. Main also caches HTML by message ID, so validate the source revision and cache invalidation before promising fresh HTML. Deduplicate in-flight body loads, keep loaded content and last measured height during same-message refresh, and disconnect the old observer before replacing it. Preserve the existing sanitized iframe, CSP, and remote-image consent. Test a slow inline attachment, a message crossing the older-group boundary, and expansion and scroll continuity.

### 6. Medium · Drafts and Outbox poll independently

**Symptom.** Drafts and Outbox do recurring view-level work on identical remote replies and can insert an error state above retained rows.

**Root cause.** [`compose-views.tsx:25`](../apps/desktop/src/renderer/src/components/compose-views.tsx#L25) writes every reply unconditionally. Drafts polls every 1.5 s and Outbox every 750 ms. The render branches preserve list data while adding errors above it. The Outbox derives a time-dependent delivery label during render, so blindly suppressing equal replies could freeze that label. [`compose-views.tsx:77`](../apps/desktop/src/renderer/src/components/compose-views.tsx#L77) [`compose-views.tsx:161`](../apps/desktop/src/renderer/src/components/compose-views.tsx#L161) [`compose-views.tsx:195`](../apps/desktop/src/renderer/src/components/compose-views.tsx#L195)

**Fix.** Keep polling where Engine delivery needs it, reconcile unchanged entities, use a stable refresh-error region, and use a small deadline-driven label for scheduled state. Keep undo, restore, confirm, and resolve behavior. Keep polling active only as required by the mounted view and existing delivery semantics.

### 7. Diagnostic · Content replacement and real renderer reloads are different

The renderer uses one `createRoot`, explicit loading states and an error boundary. The audit found no renderer Suspense boundary or sync-driven call to document reload. An Engine 401 changes the phase to unpaired, legitimately replacing the mail shell with pairing. A native renderer failure triggers one automatic recovery navigation. The startup HTML, React error boundary, Electron menu, and native recovery dialog provide explicit reload actions. Packaged Electron selects a local file and the production build excludes the dev-only fixture branch. The diagnostic distinction is top-level main-frame navigation, React component remount, and React update with retained DOM. [`renderer/main.tsx:7`](../apps/desktop/src/renderer/src/main.tsx#L7) [`renderer/index.html:12`](../apps/desktop/src/renderer/index.html#L12) [`sync.ts:161`](../apps/desktop/src/main/sync.ts#L161) [`renderer-load.ts:16`](../apps/desktop/src/main/renderer-load.ts#L16) [`main/index.ts:631`](../apps/desktop/src/main/index.ts#L631) [`main/index.ts:702`](../apps/desktop/src/main/index.ts#L702)

If the owner sees the entire native window reload, correlate main-frame navigation, render-process-gone reason, pairing phase and component mount markers. Use timestamps and reason codes with no mail fields. The existing root error boundary remains appropriate for startup failures. Give the reader and composer feature-level error handling where recovery can preserve the rest of the workspace and pending edits.

## Target architecture

Keep Electron main's SQLite replica authoritative for mail and Engine authoritative for remote draft and delivery state. Put a renderer-side query store behind the existing `AmcApi` seam. Production uses preload and tests use the synthetic adapter. The store owns IPC subscriptions, stable string or tuple keys, pending generations, cache lifetime, structural sharing and invalidation. Expose typed hooks such as `useThreadIds(viewKey)`, `useThreadSummary(id)`, `useThreadDetail(id)`, and `useSyncField(selector)`. Use `useSyncExternalStore` over cached immutable snapshots per selected value. Each snapshot must retain its reference until the observed data changes. A stable context can carry the store instance if injection is needed. Avoid streaming a mailbox snapshot through context. [React external store contract](https://react.dev/reference/react/useSyncExternalStore)

- Store ordered IDs separately from summaries and preserve existing references for equal rows. Keep a small bounded cache of reader detail and message-body versions. Deduplicate in-flight requests per key. Ignore late results on newer generations or a different pairing epoch. Batch notifications at the store boundary when a batch publishes related updates.
- Start with existing broad invalidation and active-query scoping. If IPC work remains high, send affected kinds/IDs, a replica generation and a full-reset marker after committed main transactions. Accumulate changes across the existing coalescing window and cover optimistic mutations, matching list membership/sort, account/label/count dependencies, and bootstrap completion. Retain a full-invalidation fallback for ambiguous changes. Avoid copying main's effective mailbox filtering or organise rules into React.
- Keep the pairing gate and workspace composition in `app.tsx`. A mailbox navigation module owns account, view, selected thread ID, notification-open fallback, and keyboard navigation. A search feature owns its text, request lifetime and result key. Sidebar, list, reader and dialogs subscribe where used. Hoist the minimal navigation state that genuinely crosses those features. Extract send-undo notifications and isolated dialog orchestration.
- Give the per-draft session ownership of Yjs, revision tracking, staging, autosave, uploads and send/discard coordination. Use composable header fields, editor and format controls, attachments, status/footer and dialogs. Keep transient input state in the field or editor. Save timers and version counters can remain internal until a rendered status changes. Keep stable draft IDs for session identity and small props for view components.

## Keep it that way

**React Compiler.** Feasible in the existing build, with the integration still to prove. [`electron.vite.config.ts`](../apps/desktop/electron.vite.config.ts#L30) already splits renderer plugins from main and preload. The installed Vite plugin exports `reactCompilerPreset`; v6 removed the inline Babel option. Add `babel-plugin-react-compiler` and `@rolldown/plugin-babel` to the desktop package and add a renderer-only Babel pass using `reactCompilerPreset`. Pilot pure leaf components with annotation mode and verify `react/compiler-runtime` output and behavior from both Electron dev and a packaged build. Check compiler diagnostics around TanStack Virtual and Tiptap, and test imperative editor and Radix focus behavior. Keep those areas out of the initial pilot. Compilation can skip reusable work in pure components. The data subscription scope, failed-branch unmount and blocking draft staging still require their own changes. [React Compiler installation](https://react.dev/learn/react-compiler/installation)

**Lint.** Keep Biome for formatting and its existing recommended rules. Add a renderer-only report from `eslint-plugin-react-hooks` with the TypeScript parser and recommended rules. Gate new violations for `rules-of-hooks` and `exhaustive-deps`, and baseline compiler-related diagnostics before promoting them. Review render-time mutation through refs in `use-amc.ts` and `use-hotkeys.ts`, state repair effects in `app.tsx`, and dependency suppression. Prefer fixing ownership or effect contracts to blanket disables. Put compiler lint in CI even before introducing the transform. [React Hooks lint rules](https://react.dev/reference/eslint-plugin-react-hooks) [Biome React rules](https://biomejs.dev/linter/domains/#react)

**Regression harness.** Extend the existing Vitest setup with a scoped jsdom/Testing Library renderer suite. The current pattern only discovers `*.test.ts`, so explicitly include the new harness tests. Use a typed synthetic `AmcApi` adapter with cloned replies and deferred promises, fake timers for polling and autosave, and stable ResizeObserver/list geometry. Drive one event at a time with `act`, drain only that event's tasks, and reset the ledger after mount. Use React Profiler for subtree commits and row-level probes for affected rows. A parent Profiler can fire for a local child edit, so use per-component counters or explicit region boundaries for budgets. Add a small isolated Electron test for Chromium geometry, the editor, focus, and navigation. Assert final content, focus and node identity alongside counters so a missed update cannot pass. [React Profiler](https://react.dev/reference/react/Profiler)

| Settled test | Target maximum |
| --- | --- |
| Status timestamp-only | 0 workspace, reader, list and composer commits |
| Cloned no-op change with immediate or staggered replies | 0 list, row, reader and composer commits |
| One off-reader bucket change, unchanged order | 1 changed row body, 0 sibling row bodies, 0 reader and composer commits |
| Same-key list refresh failure and retry | 0 listbox or existing row remounts, focus and selection preserved |
| One body or subject character | 0 mailbox, unrelated recipient, and unchanged footer commits, at most 1 commit in the edited UI region |
| An unchanged clean-draft poll | 0 composer content commits |
| Settled autosave and an actual remote edit | One save per local burst, updates visible after correct revision handling, editor node preserved |

Treat these as post-refactor budgets. Establish current counts first and tighten each assertion when its PR lands. Make test variants for focus, selection, response order, resync, and error recovery. Commit counts are stable CI signals. Measure duration separately in Electron and report median and tail across repeated actions at representative list sizes.

**Size guideline.** Review a handwritten renderer file at about 300 lines or a component at about 150 lines. Split when responsibilities or update rates differ, or a protocol can be owned behind an interface with a test. Keep small behaviors together and leave generated shadcn primitives on their existing path. The goal is a component API with a clear owner and implementation details that stay local.

**PR checklist**

- [ ] Name the source of truth and the component or store slice that owns new state.
- [ ] Check what updates during a no-op sync, a single changed row, and typing if the diff touches these paths.
- [ ] Verify stable domain keys, selection, focus, scroll, and mounted DOM during refresh and retry.
- [ ] Exercise slow, failed and out-of-order responses. Show an empty state only for an accepted result.
- [ ] Preserve draft durability, reviewed revisions and send/undo semantics for edits to composer or delivery.
- [ ] Run the scoped tests and `pnpm check`. Use synthetic data for shared traces and screenshots.
