# Smart Inbox v1

Reviewed against main at `8efb958`. [AMC build plan](../plan.md) describes M7's intended behavior. This spec uses the shipped code for the baseline. The open PR list was empty at review time, including the Superhuman research PR. The keyboard design below follows AMC's current bindings.

## Goals and scope

- Make sender identity easier to scan with Engine-cached logos and coloured initials. Show the sender's address in review so branding never substitutes for identity.
- Keep new-sender mail in the Inbox. Put a soft screener above the other sections, with one card per new Sender in the current Inbox scope. Accept keeps mail in the Inbox. Block moves matching Inbox mail and matching future arrivals to AMC's **Screened out** Label, backed by a Gmail user Label or an IMAP folder. Screened out is reversible and separate from provider Spam.
- Make triage a focused, keyboard-first review of New senders followed by lower-confidence Bucket assignments. Reuse Organise, the composer, and Undo.
- Ship a fixed section order and local collapse preferences. Defer hard screening, domain-wide rules, user-defined sections, custom shortcuts, remote contact pictures, full BIMI mark verification, Agent approval automation, and an interrupt-policy redesign.

## Domain model

- **Sender** means a single parsed From mailbox. Scope its rule and known-sender evidence to an Account. Match the normalized full address, never display name, Reply-To, or domain. Use AMC's case-insensitive address convention and normalize international domain names to ASCII. Keep plus tags, dots, and aliases distinct. Missing, invalid or ambiguous From uses display fallback and has no sender action. Exclude the owner's configured addresses from screening.
- **Sender rule** is an explicit owner decision, accepted or blocked, with revision and action provenance. No rule is the default. **Known sender** means accepted or observed as a recipient of confirmed outbound mail from that Account, including replies. Block takes precedence over outbound evidence. Reading, starring, contact import, a draft, and Agent suggestions confer no trust.
- **Screened out** is a recoverable destination. A Thread with both screened and unscreened messages can remain in Inbox. The sender-level move applies only to matching incoming Inbox messages.
- **Section** is a visible Inbox partition. **Seen** means read mail with no active Reply, Action, or Follow-up assignment and no owner action on the current Inbox arrival. **Triage queue** is a review-session snapshot of sender cards and Threads. **Confidence** is a review hint from triage, associated with the exact Inbox input it classified. A **triage correction** is an owner-confirmed Bucket choice recorded as a prompt example. [Glossary](../../GLOSSARY.md)

## Engine contracts and persistence

The schema currently ends at migration 20. Bucket columns already exist (v12), as do `mutation`, `mutation_message`, the Organise intent tables (v8), and `agent_action` (v10). Bucket writes currently persist the assignment and actor, with no confidence or durable learning history. Use forward-only additive migrations, reserving numbers after rebase. Defaults permit existing mail, tokens, and older Clients to operate during rollout.

- **Sender state.** Add `sender_rule(account_id, address, decision, revision, action_id, decided_at)`, Account-scoped outbound evidence, and one managed destination mapping per Account. Use exact message identity when recording outbound evidence so reimport and duplicate Sent copies are idempotent. Record confirmed outbound recipients and import provider Sent; rebuild from sent-message envelopes in bounded restartable batches. The existing `contact.sent_count` is global and cannot prove which Account sent mail. Keep sender status unresolved during initial evidence import and show mail in its normal section until the evidence read is ready. Later historic Sent backfill can remove cards. It must never create rules or move mail.
- **Replica contract.** Project an optional current Inbox Sender key and status on `ThreadSummary`, derived from the newest eligible incoming Inbox message. A stable per-message screening disposition covers notification eligibility, including when another sender keeps the Thread in Inbox. Use the existing change log and snapshot path so a rule/evidence change refreshes only affected Inbox summaries. Preserve defaults for old rows and do not carry a Sender status across Accounts or pairing changes. For a mixed Thread, the card displays the exact Sender targeted. The Engine resolves all matching messages in Inbox independently of which Sender the Thread displays.
- **Corrections and eligibility.** Add nullable confidence with producer/input revision to the current Bucket result, plus a bounded-query correction table with Account, Thread and input revision, previous assignment, chosen Bucket, owner action ID, and undo state. Add an owner-handled watermark keyed to the latest incoming Inbox message identity for owner Bucket changes and verified replies. Archive and Snooze normally remove the Thread from this projection already. New inbound advances the watermark input. Compare source revision in the same transaction as the Bucket write. Existing assignments with absent confidence remain unknown rather than being reclassified as low. Undo of a correction restores the prior state if still current and excludes the reverted example from subsequent prompts.
- **Owner action history.** Extend Organise action status with an owner action record and child mutation links. Record compare-and-set revisions, affected message IDs, action outcomes and inverse status. Keep correction and rule history in the backed-up database.
- **Logo cache.** Add a separate disposable index keyed by exact normalized sender domain and source (BIMI or favicon), with result kind, content digest, fetch/expiry timestamps and bounded retry metadata. This lets a domain serve favicon for one message and BIMI for another with trusted evidence. Store only resized PNG bytes in an evictable Engine cache. Use the Host's existing storage layout and separate cache lifetime from the backed-up mail/action database. Restore with an empty avatar cache.

### Provider sync and Screened out writeback

- Evaluate candidates in the Engine's provider ingestion path using authoritative Inbox membership. Gmail snapshot/history in `providers/gmail/sync.ts` and IMAP Inbox scans/reconciliation in `providers/imap/sync.ts` feed a shared idempotent screening service. Commit observation and work enqueue together before advancing provider cursors. A follow-up worker discovers unfinished work on restart. Avoid writing inside a sync scan or IMAP mailbox lock. Existing Inbox messages are evaluated when Block is applied. Future candidates include eligible Inbox imports while the rule is active. Provider Spam/Trash, Sent, Drafts, and archived history remain untouched. An external manual return to Inbox is explicit and wins for that message if it was already screened under the same rule revision.
- Serialize provider writes through Organise's existing per-Account queue, write epochs and verified journal. Use a durable unique key over rule revision and message identity, with child mutation IDs. Check the active revision and exact source immediately before dispatch. Preserve destination identity through reimports (IMAP uses verified location and UIDVALIDITY, with existing rebind logic). A deleted or ambiguously renamed managed destination stops screening and exposes a repair state. Provision lazily on first Block. If the requested name already exists, show a conflict and ask the owner to choose whether to adopt it. Never silently adopt or create duplicates after an ambiguous provider response.
- **Gmail.** Reuse label creation and journaled message-level writeback. Add the custom Label and remove INBOX for exact current message IDs as one modify request where supported. Preserve other Labels and read/star state. Reconcile optimistic projection with provider history and Undo only the acknowledged deltas that still match the journal checkpoints. Never issue provider Spam, thread-wide Archive, or Trash to implement screening.
- **IMAP.** Create a normal destination folder and map it as an AMC Label. Reuse Organise and `ExactUidImapFlow`. Use UID MOVE, or with UIDPLUS use UID COPY then UID STORE for that source UID and UID EXPUNGE for that UID only. Capture source/destination mailboxes, UIDVALIDITY and verified destination UID via COPYUID or the same unambiguous verification Organise uses. Never broad EXPUNGE. Without either safe capability, disable Block for that Account before creating the rule. On ambiguous or partial copy/removal, use existing journal/incomplete-copy handling and report failed or partial. Never guess a target UID to move, delete, or undo. [MOVE](https://www.rfc-editor.org/info/rfc6851/) · [UIDPLUS](https://www.rfc-editor.org/info/rfc4315/)
- **Pending state and notifications.** While screening is pending keep mail recoverable and show pending/error state. Gate notifications at the message level before desktop candidate collection and again before display, including mixed Threads, late batches and cold bootstrap. A permanently failed delivery stays reachable in Inbox with a repair notice. Code today batches recent unread arrivals in `main/notifications.ts`; keep its quiet hours, deduplication and arrival-time gates. New-sender and avatar changes themselves do not generate notifications.

### Undo and failure semantics

The existing Organise journal is the authority for provider inverses. Do not use the Agent log as an owner mutation queue. Extend the owner action history to record rule transitions and correction changes, using the same Undo surface and exact IDs.

- Accept Undo restores the previous rule (outbound evidence still counts). Block Undo creates a new revision, stops further screening, cancels queued old-generation work, and queues inverses for verified child moves from that Block, including mail screened after the first move. Handle in-flight acknowledgements before finalizing the inverse set. Restore only original Inbox membership/location and AMC deltas, subject to existing provider verification and supersession. Keep unresolved copies and external changes visible in partial status. Clearing a rule stops future screening and leaves older messages in the destination. The owner can restore previously screened mail with explicit Undo or Organise.
- Archive/Snooze use existing exact mutation Undo and feature/capability gates. Section Mark seen captures the visible unread Thread IDs and uses standard Organise thread-level read actions. Report failures through Organise and preserve each Thread action's Undo entry.
- Skip is local and undoable by restoring queue position. Reply opens the existing owner composer and holds position. Cancel, save or close returns to the same item with any draft preserved. On explicit Send, reuse Outbox cancellation within the existing send-Undo window. Advance when delivery is explicitly queued, link its Outbox ID, and record the handled watermark only after confirmed send. Delivered mail cannot be recalled. Surface that boundary and keep the composer send confirmation, review and no-send policy. No review key sends mail.
- Use idempotent client action IDs for retries and reject stale revisions with a refresh/retry path. Disable repeat submission while pending. Queue may advance once the Engine has durably accepted intent, with a persistent error/Undo surface and a way to return to a failed card. Proof of an inverse is required before claiming it succeeded.

### Filter out

- **Filter out** moves the selected Thread's eligible incoming Inbox messages to the Account's **Filtered** Label. **Restore to Inbox** returns eligible messages. Both use verified Gmail label changes or exact IMAP UID MOVE or UIDPLUS COPY and UID EXPUNGE. The Engine journals each message and supports Undo.
- In the desktop Thread list and reader, **!** (Shift+1) applies Filter out and **F** opens Forward. The Thread toolbar and list context menu offer Filter out for Inbox Threads and Restore to Inbox for Filtered Threads.
- The classifier submits independent Bucket and Filter predictions. Phase 1 presents Filter suggestions in review. Explicit owner intent queues provider work.
- The Decision log records owner judgments and predictions against the exact arrival and mailbox generation. Undo appends a retraction. The Engine keeps optional owner reasons in its private reason store. Shift+F and Shift+X open the reason input. An installation can disable capture with `AMC_PRIVATE_TRIAGE_REASONS=0` at Engine startup and `VITE_AMC_PRIVATE_TRIAGE_REASONS=0` at Desktop build time. See [Owner preferences](owner-preferences.md).

### Avatar fetching and safety

1. Use a versioned, tested webmail domain list on the Engine (initial entries gmail.com, googlemail.com, outlook.com, hotmail.com, live.com, msn.com, yahoo.com, icloud.com, me.com, mac.com, aol.com, proton.me and protonmail.com). Match exact registered domains and their subdomains at label boundaries, with no DNS or HTTP for these addresses. Choose initials from display name or local-part, using grapheme segmentation and a deterministic accessible palette hashed from the normalized address. Reserve a fixed-size slot in every case.
2. For eligible From domains, try `default._bimi.<domain>` TXT with a strict single BIMI1 record and HTTPS logo URI. Prefer this source only with trustworthy aligned authentication evidence for the message where the provider exposes it, never an arbitrary message header. A cache hit cannot bypass the message gate. v1 does not validate mark certificates or expose verification badges. If reliable provider-aligned evidence is absent, fall through to the favicon. Defer custom selectors and parent-domain BIMI discovery. Validate the source-selection contract against provider test Accounts before enabling BIMI; a provider can ship fallback while evidence is unavailable. [BIMI Group implementation guide](https://bimigroup.org/implementation-guide/)
3. Next try `https://<domain>/favicon.ico`. v1 uses this conventional first-party path only. ICO and supported raster types are decoded and re-encoded. SVG, including for BIMI, passes a strict static allowlist and isolated rasterization with networking and file loading disabled. Reject external references, active content, DTDs, entities, animation, embedded nested data, and unrecognized formats. Never serve raw SVG or remote URLs. Failures fall through to initials.
4. Treat DNS and URLs as untrusted. Accept public DNS names and HTTPS on port 443. Block userinfo, IP literals, non-public IP ranges (including IPv4-mapped IPv6), private DNS zones, and special-use names. Resolve and check every address including redirect targets, pin the vetted address to the actual connection, and preserve hostname certificate validation. Cap redirects at two and limit favicon redirects to the original registrable domain. Apply the same destination policy to BIMI hosts even when DNS advertises an external CDN. Enforce the egress policy at the outbound boundary too. Send no cookies, credentials, referrers, full sender addresses, or subject/message data. Use no tracking URLs taken from message bodies and no Google favicon, Gravatar, or other avatar service.
5. Start with a 4-second total per-domain lookup budget (including DNS), 256 KiB input cap enforced during streaming and decompression, 1024×1024 maximum decoded dimensions, and a 64×64 PNG output with a 32 KiB limit. Bound decoder CPU/memory, queue depth and cache size. Deduplicate by domain and run at most four lookups at once. Cache a positive hit for seven days, definitive misses for 24 hours, and transient failures for 15 minutes with backoff. Evict least-recently-used entries. Refresh only on demand and keep the prior safe asset through a bounded seven-day transient error grace period. Stop serving stale pixels immediately when the sender gate changes or a previously eligible source becomes unsafe. Log outcome classes and durations without raw URLs, addresses, or message IDs.
6. Schedule demand from visible mail via the existing desktop process boundary. The Mac and CLI only access the paired Engine. Main fetches authenticated PNG, verifies type/size and hands the renderer local bytes via a bounded cache and existing CSP-compatible local image handling. Coalesce visible requests and refresh only mounted consumers for a changed digest. CLI reports source/initials and can explicitly write cached PNG bytes to a file. No assets travel in replica snapshot pages. Missing/offline images always leave initials usable.

## Desktop

### Sectioned Inbox

In the unfiltered Inbox (Unified and single Account), render these exclusive sections in the order below. Membership takes the first matching predicate, with Seen evaluated immediately before the Other mail catchall. Existing search, filtered results, and other views keep the normal Thread list.

Show a Section from its first Thread or Sender card until its last entry leaves. Determine presence from all entries before applying collapse or the Other mail preview. A collapsed Section or a Section with zero unread entries still shows its header while it has entries. Keep its collapse preference when it disappears. An empty Inbox shows **Inbox is clear** and **New mail will appear here.**

| Section | Membership |
| --- | --- |
| New senders | New Sender on the representative incoming Inbox message, grouped by Account and address. One card with count and newest Thread. Open a scoped list for that Sender when there is more than one Thread. A card carries the literal From address and Account. |
| Action/Reply | Reply or Action Bucket, including read Threads with outstanding assignments. |
| Follow-up | Follow-up Bucket, including read Threads with outstanding assignments. |
| Other mail | Remaining Inbox Threads, including Update, Later, When I have time, unassigned, and read Threads with an owner action that remain in Inbox. Preserve original Bucket badges. |
| Seen | Read and unactioned for the current Inbox arrival. |

Within each section use unread first, then newest activity, then stable ID. A sender card is unread if any represented Inbox Thread is unread. Default Other mail to a three-row preview plus **Show all** when there are hidden rows. Other sections start expanded. Every section has a separately persisted collapse control and per-section **Mark seen**. Mark seen captures the unread Threads represented by the section's currently exposed rows, including every unread Thread represented by an exposed sender card. Collapsed sections and rows behind Show all are excluded. Standard Organise thread-level read semantics apply to each captured Thread. It does not accept Senders or clear action Buckets, so some read Threads remain where they were. Do not infer acted state from a read operation. Display Section counts including hidden rows.

Use **Other mail** for the fallback section because **Update** is a specific triage Bucket. Thread row badges preserve the assigned Bucket. Their tooltip and the reader identify it as **Triage**. The section keeps its existing internal key so saved collapse preferences still apply.

```text
MailWorkspace
  MailPanes
    SectionedInbox
      SectionHeader (collapse, count, Mark seen)
      SenderCard or existing ThreadRow subscriber
      ShowAll control (Other mail)
    existing ThreadReader
  TriageWorkspace (one active card when in review)
    Progress and status
    SenderCard or Thread preview
    Action bar
  existing ComposeOverlays and Undo toasts
```

- The Engine owns sender status, Bucket/confidence, and provider state. Desktop main/preload transport typed replica fields and commands. Extend the query-local `ThreadIndex` in `data/thread-queries.ts` or add a sibling projection. Derive membership incrementally from relevant changes in the selector cache and structurally share unchanged card data, section arrays and summaries. The existing bounded replica list cannot stand in for the whole Inbox. Provide stable pagination or indexed replica reads so every Thread is reachable and Mark seen can address every exposed row regardless of the mounted virtual window. Maintain individual selectors for section counts, order, and row/card content. Use `data/selection.ts` and the active Inbox query key for selection continuity. No parent subscription to the full index or all row values.
- Extend the existing TanStack virtualizer into one keyed flat stream of headers, rows/cards and footer controls. Keep stable item ID across section moves. Recalculate positions without re-rendering unaffected row bodies. Measure variable header/card heights and preserve scroll anchor. Keep virtualized focus targets mounted until focus changes. On collapsed or removed selection use the next visible item, then previous, then the header. Keep cached rows on same-key background failure and resnapshot. Authoritative empty state can clear them. Scope preferences by pairing and Account or Unified in a versioned local setting, and clear transient state on identity changes.

### Keyboard and triage mode

- Inbox `j/k` (and existing arrows) traverses visible cards and Thread rows across sections. Shift+J/K lands on the next/previous visible section header, including collapsed ones. When a focused header disappears and the list remains, return focus to the list. Enter or Space activates its collapse control. Provide an accessible focus route to the explicit Mark seen and Show all buttons. Preserve ordinary button activation and reader Space outside triage. Reassign Handoff from `t` to Shift+T, keeping its toolbar and palette action. Update `use-mail-commands.ts`, shortcut help and labels together. Verify Shift+T and Shift+J/K against the current hotkey map and Electron menu accelerators.
- `t` opens triage from the Inbox when no draft or overlay owns the keys. A palette action provides the same entry. Use the window's main content area rather than changing macOS fullscreen mode. Mount one card at a time. An exclusive command map suspends mailbox commands and defers to composer, Snooze picker, confirmation popover, menu, typing, IME and screen-reader button interactions. The inbox's `a` is Reply all, `s` is Star, `h` is Snooze, `u` is Mark as read and `z` is Organise Undo. Preserve those outside triage.
- Inside triage, `a` accepts, `x` blocks, `1–6` chooses Reply, Action, Follow-up, Update, Later or When I have time in existing `BUCKETS` order, `e` archives, `s` opens Snooze, `r` opens Reply then returns, Space skips, `u` undoes the most recent triage action, and Esc exits keeping position. **F** applies Filter out. **Shift+F** and **Shift+X** open the optional inline reason input when private reason capture is enabled. Enter applies the action and Esc cancels the input. Action history supports editing reasons for Filter out and Block sender. Sender-rule commands act on the address shown on the card, with accessible action labels spelling out the consequence. On a grouped sender card, thread-level actions target the explicitly named representative Thread only. When other matching Threads remain eligible, retain that sender card with the updated representative rather than silently completing it. For low-confidence Thread cards, sender actions require an eligible From address. Disable repeated write keystrokes and explain unavailable actions (e.g. no safe IMAP move, no reply target, or Snooze disabled). Preserve native Space on focused buttons.
- Form the queue with new Sender cards first, then low-confidence current Inbox Threads, excluding those represented in the first group. Mail from a configured owner address is excluded from the new-sender index across Accounts, including paired IMAP deliveries. It can still enter Thread review with a current low-confidence Bucket prediction or Filter suggestion. Use explicit `low | medium | high` with a short reason and collect other explicit below-high cases only if owner feedback justifies it. Low initially means the classifier cannot choose confidently between Buckets using the available context. Treat model confidence as a heuristic, with no numeric probabilities in v1. Use stable newest-first order within each group, ID tie-breaks, and a capped session snapshot (e.g. 100 cards) with another batch available on completion. Retain the order and total for progress such as **4/17**. Work arriving mid-session waits for a new session. Revalidate a card on display and on write; report stale targets, skip ineligible cards and preserve the rest. Scope saved queue IDs and cursor to pairing and Account with a versioned local record, resume across exit/re-entry and app restart, and clear on identity change. Skip lasts for the session.
- Loading, retryable error and an authoritative **You're caught up** are distinct. Keep the last card when a retry or pending refresh can still use it. Show queued/offline or partial states honestly and provide an Undo toast backed by the exact action ID plus accessible action history. Keyboard Undo restores the card when it remains eligible. Asynchronous failure remains discoverable after mode exit. Restore focus to the initiating row/control on exit or fall back to the Inbox heading. Composer return restores the card focus without discarding a draft.
- Use headings, disclosure buttons with `aria-expanded` and `aria-controls`, readable counts, and a polite live region for card progress and action results. Keep buttons outside `role=option`; if cards have controls, use native grouped lists with roving focus and retain Thread selection semantics through a labelled navigation surface. Initials and logos are decorative alongside announced Sender names. Ensure visible focus, accessible colour contrast, and no hover-only actions. Keep section collapse and card navigation immediate. If a status transition uses motion, use a short opacity transition, disable it in reduced motion, and avoid layout animation and focus delays.

## CLI

- `amc senders list [--account <id>] [--status <status>] [--json]`, `amc senders accept|block <address> --account <id>`, and `amc senders clear <address> --account <id>` use owner HTTP. Prompt-free calls show the action ID, Account, and pending or final status. A partial result exits nonzero with status detail. Add an exact owner Undo entry (e.g. `amc senders undo <action-id>`).
- `amc triage queue [--account <id>] [--limit <n>] [--json]` returns the same snapshot order and typed card IDs as desktop. Keep existing `amc triage --account …` behavior as the default operation and explicitly test Commander argument parsing for existing flags and the new subcommand. `amc bucket` can feed owner corrections when submitted as a review intent. Keep legacy callers compatible.
- `amc senders avatar <message-id> [--out <file>]` reads Engine fallback/source metadata and optionally writes a cached raster. It has no remote URL parameter. Do not put PNG bytes in JSON output.

- `amc triage filtered` lists Filtered Threads and their revisions. `amc triage filter <thread-id> --revision <n>` applies Filter out. `amc triage restore <thread-id>` restores a Thread to Inbox. Private reasons, when enabled, use `--reason-file <path>` or `--reason-file -` for stdin.

## Risks and open questions

- **Address spoofing.** Sender rules match From, which is a mailbox string and can be forged. Show exact address and Account. A rule changes Inbox handling only. It does not bypass provider security. Gate BIMI separately on trusted aligned evidence and ship initials/favicon if provider evidence cannot be established.
- **Provider reversibility.** Some IMAP servers can move a message without supplying a verifiable destination UID, and external changes can supersede either provider's inverse. Test the owner's provider capabilities before enabling Block and report honest per-message failures. The plan assumes any acceptable v1 provider can verify its inverse via the existing Organise strategy.
- **New-sender noise.** First rollout may show many current Inbox senders. Scope to actual Inbox, group by Account and address, and measure after Sent evidence backfill. The proposed account-local trust, queue cap, one low-confidence tier, and placement of read outstanding assignments are v1 defaults to verify with the owner.
- **Privacy and storage.** Direct domain lookups disclose Host IP and domain interest to DNS and destination operators. Lazy, shared cache refresh reduces exposure. Keep webmail fetch-free and publish the behavior with an Engine-side kill switch for remote avatars. Check safe resolver behavior and Host cache headroom in the deployment context.
- **Managed destination and Undo retention.** Measure provider folder rename/delete behavior and journal growth. Keep provenance for active block generations backed up so future-message Undo remains explainable after restart. Expose owner remediation for missing journals or deleted messages. Confirm retention and whether the owner wants bulk restoration after clearing a rule in a later release.
